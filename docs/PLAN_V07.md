# Persian model marketplace

## Buyer decisions

1. Start with a Persian-language task: speech recognition, translation, speech
   synthesis, OCR, document extraction, semantic search, classification or chat.
2. Choose API access or model weights. A single model version can offer both.
3. Compare API consumption with the existing calculation engine. Compare weights
   by their one-time license price, with usage rights beside the amount.
4. Inspect the publisher, training-data description, supported Persian variety,
   input/output example, deployment requirements and limitations.
5. Follow an existing seller link, download public weights, or prepare a purchase
   request for a private listing. Never imply payment or delivery has occurred.

## Information structure

- Default home: Persian-specialized models. International models and GPU remain
  separate, reachable catalogs. Language support alone is not specialization.
- Product: one identity/version; separate API and weights choices. Cheapest API
  provider stays above other providers. Weight purchase shows license duration,
  allowed modifications, redistribution restrictions, file format and support.
- Publisher: person or organization; no fabricated verification badge or review.
- Seller workspace: create, edit, preview, save and export listing drafts. Ask
  for dataset provenance rather than uploading private training examples.
- Request workspace: browser-local saved purchase requests with JSON export.

## Minimal architecture

Keep FastAPI, plain JS/CSS and the portable HTML exporter. Extend products with a
Persian capability card. Keep API/GPU offers separate from weight-license offers.
Add page and request billing to the Python engine; never add JS price arithmetic.
Reuse routes, safe HTML helpers and local persistence. No authentication, payment,
file-delivery or messaging claims without an actual integration.

The user's latest instruction authorizes illustrative uptime. Keep deterministic
presentation metrics in their own fixture file, never as measured observations
or in the existing historical request-success dataset. Weight files have no
service uptime; their page explains that availability depends on deployment.

## Verification gate

- Original 49 products keep all three price presets unchanged.
- API and one-time weight prices never share a ranking or estimate total.
- API-only, weights-only and dual-access products have working paths.
- Filters preserve task, access, publisher type and Persian scope in URLs.
- Draft validation rejects incomplete licensing, unsafe links and invalid money.
- Persistence failure is visible; no false save or send confirmation.
- Every visible action navigates, changes state, saves locally or exports a file.
- Export embeds every asset and works without file-origin requests.
- Record DOM checks separately from browser layout checks.
