# بررسی نسخه ۰.۱۴

در این تغییر، مسیرهای جابه‌جایی فهرست و تب‌های دریافت یک مدل با رفتار اعمال مصرف یکدست شدند.

## نگاه خریدار

کاربر در میانه فهرست، صفحه بعد یا فیلتر جدید را انتخاب می‌کند. نتیجه قبلی تا آماده شدن نتیجه جدید می‌ماند؛ وضعیت بارگذاری دیده می‌شود و کاربر به بالای صفحه پرتاب نمی‌شود. حرکت خود کاربر در زمان بارگذاری هم حفظ می‌شود. همین رفتار برای تب API و وزن‌های همان مدل برقرار است.

## پیاده‌سازی

- تغییر دسته، فیلتر، ترتیب، تعداد نتیجه و شماره صفحه از مسیر مشترک انجام می‌شود.
- بارگذاری فهرست ۵۵۰ میلی‌ثانیه و تب دریافت مدل ۶۰۰ میلی‌ثانیه است؛ تنظیم کاهش حرکت مرورگر این مکث را حذف می‌کند.
- محتوای قبلی هنگام بارگذاری ثابت می‌ماند. پیشنهادهای قدیمی موقت غیرقابل انتخاب هستند؛ کنترل‌های ناوبری برای انتخاب جدید در دسترس می‌مانند.
- آخرین انتخاب معتبر اجرا می‌شود. کلیک تکراری کار را تکرار نمی‌کند؛ تغییر مصرف می‌تواند جابه‌جایی در انتظار را لغو کند.
- اسکرول عمودی و موقعیت نوار دسته‌ها حفظ می‌شود. فوکوس صفحه‌کلید با preventScroll برمی‌گردد. فهرست کوتاه‌تر فقط فضای پایین لازم برای نگه داشتن موقعیت را رزرو می‌کند.
- خطای ساخت فهرست، محتوای قبلی را برمی‌گرداند و بارگذاری را آزاد می‌کند. خطای قیمت در تب API مسیر تلاش دوباره دارد.
- لینک‌ها واقعی می‌مانند و کلیک با Ctrl یا Command قابل استفاده است. تغییر نشانی از history انجام می‌شود؛ در محدودیت file-origin، مسیر جایگزین hash که باعث پرش شود وجود ندارد.
- ورود به محصول جدید از بالای اطلاعات همان محصول است؛ تکمیل دیرتر قیمت، اسکرول کاربر را دوباره تغییر نمی‌دهد.

## نتیجه بررسی

۱۵ سناریوی ناوبری، ۸ سناریوی مصرف، ۶۲ مسیر محصول و ۸۲ سناریوی گروهی HTML مستقل، ۳ سناریوی نسخه سروری و ۳ بررسی ساختار CSS پاس شدند. داده‌ها، تعرفه‌ها و منطق محاسبه نسبت به نسخه ۰.۱۳ تغییری نکردند. نتایج آزمون‌های محاسباتی نسخه ۰.۱۲ در گزارش قبلی حفظ شده‌اند و در این تغییر دوباره اجرا نشده‌اند.

این بررسی‌ها اجرای DOM و رویدادها و فرمان‌های اسکرول هستند؛ نمایش واقعی مرورگر، اسکرول لمسی و رفتار file-origin در ویندوز در این محیط بررسی نشده‌اند. هیچ درخواست واقعی به ارائه‌دهنده ارسال نمی‌شود.
